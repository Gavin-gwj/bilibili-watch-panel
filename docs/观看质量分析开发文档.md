# 观看质量分析开发文档

> 适用项目：Bilibili Watch Panel
> 
> 当前基线：v0.3.1，单文件 Tampermonkey 用户脚本
> 
> 交接用途：可直接复制给下一个开发对话使用

## 1. 可直接交给 Agent 的任务

请在当前 Bilibili Watch Panel 项目中新增“观看质量分析”功能，保持现有技术约束和隐私声明：

- 继续使用原生 JavaScript、Shadow DOM、`GM_getValue/GM_setValue` 和 Chart.js。
- 不新增服务器、不上传观看数据、不改变现有四个 Tab 的主要结构。
- 在现有记录基础上支持：完播率、单视频观看进度、重复观看次数、平均单视频观看时长。
- 兼容旧版 JSON 备份和已有 `watchRecords` 数据；旧记录缺失新字段时按文档中的默认值处理。
- 先更新数据采集、统计和 UI，再补充测试清单与 CHANGELOG。
- 完成后运行 `node --check bilibili-watch-panel.user.js`，并进行浏览器手工验证。

## 2. 功能目标

| 指标 | 定义 | 展示位置 |
| --- | --- | --- |
| 完播率 | 统计范围内达到完播判定的视频记录数 / 有效视频记录数 | 今日、本周、全部，报告可选 |
| 观看进度 | 单条记录已观看的最高播放位置 / 视频总时长 | 观看记录列表、详情信息 |
| 重复观看次数 | 同一视频在统计范围内的有效播放会话次数，首次观看不算重复 | 观看记录列表、Top 视频 |
| 平均单视频观看时长 | 统计范围内累计有效观看秒数 / 去重后视频数 | 今日、本周、全部 |

### 2.1 统计范围

- 默认按现有记录的 `date` 过滤，保留本地时区口径。
- “视频数”继续按 `date + bvid` 记录数统计，避免破坏现有面板结果。
- 跨日期观看产生两条记录时，完播率按两条日期记录分别统计；“全部”Tab 合并时可按 `bvid` 去重。
- 无 `durationSeconds`、总时长为 0、或视频信息不完整的记录不进入完播率分母，但仍进入观看时长统计。
- 所有比率都限制在 `0% - 100%`，无有效样本时显示 `—`。

## 3. 数据模型

现有记录按 `date + bvid` 合并，在 `WatchRecord` 上增加以下可选字段：

```js
{
  id: "2026-10-03_BVxxxx",
  date: "2026-10-03",
  bvid: "BVxxxx",
  videoTitle: "视频标题",
  uploader: "UP 主",
  uploaderId: "123456",
  timestamp: 1760000000000,
  lastActive: 1760000300000,
  watchedSeconds: 314,
  openCount: 2,

  // 新增字段
  durationSeconds: 1260,
  maxPositionSeconds: 1040,
  playCount: 3,
  completed: false,
  completedAt: 0
}
```

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `durationSeconds` | `number` | `0` | 最近一次获得的有效视频总时长；只接受有限正数 |
| `maxPositionSeconds` | `number` | `0` | 当前日期记录中达到过的最高 `video.currentTime` |
| `playCount` | `number` | `1` | 有效播放会话次数；至少为 1 的历史记录按 1 处理 |
| `completed` | `boolean` | `false` | 是否达到完播判定 |
| `completedAt` | `number` | `0` | 首次达到完播判定的时间戳 |

### 3.1 字段关系

- `watchedSeconds` 是累计有效观看时长，允许因重复观看超过视频总时长。
- `maxPositionSeconds` 用于计算观看进度，不能用 `watchedSeconds / durationSeconds` 代替，否则重复观看会造成进度超过 100%。
- 单条记录进度：

```js
progress = durationSeconds > 0
  ? Math.min(1, maxPositionSeconds / durationSeconds)
  : null;
```

- 重复观看次数：`Math.max(0, playCount - 1)`。现有 `openCount` 继续表示当天打开次数，不强行改变其语义。

### 3.2 旧数据兼容

在 `sanitizeRecord()` 中补齐字段：

```js
durationSeconds: Number.isFinite(r.durationSeconds) && r.durationSeconds > 0
  ? r.durationSeconds : 0,
maxPositionSeconds: Number.isFinite(r.maxPositionSeconds) && r.maxPositionSeconds >= 0
  ? r.maxPositionSeconds : Math.min(Number(r.watchedSeconds) || 0, Number(r.durationSeconds) || 0),
playCount: Number.isFinite(r.playCount) && r.playCount > 0
  ? Math.floor(r.playCount) : Math.max(1, Number(r.openCount) || 1),
completed: r.completed === true,
completedAt: Number.isFinite(r.completedAt) ? r.completedAt : 0,
```

旧记录没有可靠的播放位置，不能根据观看秒数直接推断完播；因此旧数据默认 `completed = false`，新字段从升级后开始积累。

## 4. 采集层改造

### 4.1 视频总时长

在 Collector 会话初始化和 `loadedmetadata` 事件中读取：

```js
const duration = Number(video.duration);
if (Number.isFinite(duration) && duration > 0 && duration < 24 * 60 * 60) {
  this.videoInfo.durationSeconds = duration;
}
```

采集优先级：`video.duration` > 页面已加载的视频信息 > `0`。不为获取总时长增加接口请求。

### 4.2 有效播放会话

一次会话指视频从暂停或未开始状态进入 `play`，直到暂停、结束、切后台、切换视频或页面关闭。

- Collector 首次确认当前视频时，保留现有 `openCount` 逻辑。
- 每次从非播放状态进入 `play` 时，`playCount += 1`；首次自动进入播放时初始化为 1，避免重复触发事件导致多加。
- 只有 `video.currentTime` 实际推进且页面可见时，才累计 `watchedSeconds`。
- `maxPositionSeconds = Math.max(maxPositionSeconds, video.currentTime)`。
- 播放结束时将 `completed` 设为 `true`，并写入第一次完播时间 `completedAt`。

### 4.3 完播判定

按以下顺序判定，避免不同播放器事件差异：

1. 收到 `ended` 事件，且 `durationSeconds > 0`。
2. 当前播放位置满足 `currentTime >= durationSeconds - 2`。
3. 或进度达到 `0.95` 且当前时间已稳定推进，作为播放器未触发 `ended` 的兜底。

判定后只允许从 `false` 变为 `true`，不因后续数据刷新回退。建议常量：

```js
COMPLETION_TOLERANCE_SECONDS: 2,
COMPLETION_PROGRESS_THRESHOLD: 0.95,
```

## 5. Stats 统计接口

在现有 `Stats` 模块中新增纯函数，避免 UI 自己重复计算：

```js
Stats.quality(records, options)
Stats.recordProgress(record)
Stats.completionRate(records)
Stats.averageVideoDuration(records)
Stats.repeatWatchCount(records)
```

推荐返回结构：

```js
{
  validProgressCount: 12,
  completedCount: 7,
  completionRate: 0.5833,
  averageProgress: 0.681,
  totalWatchedSeconds: 3580,
  distinctVideoCount: 10,
  averageVideoDuration: 358,
  repeatWatchCount: 4,
  recordsWithoutDuration: 2
}
```

### 5.1 统计公式

| 指标 | 公式 |
| --- | --- |
| 单条进度 | `min(1, maxPositionSeconds / durationSeconds)` |
| 完播率 | `completedCount / validProgressCount` |
| 平均进度 | 有效记录进度的算术平均值 |
| 平均单视频观看时长 | `sum(watchedSeconds) / distinctVideoCount` |
| 重复观看次数 | `sum(max(0, playCount - 1))` |

“全部”Tab 如按 BV 去重，应先按 `bvid` 聚合：

- `watchedSeconds` 取总和。
- `maxPositionSeconds` 取最大值。
- `durationSeconds` 取最新有效值。
- `completed` 取任一记录为 `true`。
- `playCount` 取总和。

## 6. UI 方案

### 6.1 今日 Tab

在现有数字卡后增加“观看质量”区块，推荐四个小指标：

- 完播率
- 平均进度
- 重复观看
- 平均单视频时长

今日观看记录每条增加：

```text
观看 3分14秒 · 进度 82% · 重看 1 次
```

无总时长的记录显示“进度未知”，不显示误导性的 0%。

### 6.2 本周 Tab

增加两张图或合并为一个质量区块：

1. 每日完播率折线图。
2. 每日平均观看进度柱状图。

图表必须沿用现有 `makeChart()` 生命周期：只在打开 Tab 时创建，关闭面板时销毁。

### 6.3 全部 Tab

增加质量摘要和筛选：

- 完播率、平均进度、重复观看次数、平均单视频观看时长。
- 记录列表增加“进度”和“重看次数”字段。
- 增加筛选项：全部 / 已完播 / 未完播 / 进度未知。

### 6.4 报告 Tab

报告中增加一行简短总结，例如：

```text
本周看完了 7 / 12 个视频，平均观看进度 68%，重复观看 4 次。
```

当有效样本不足时使用：

```text
本周已有 4 条观看记录，视频总时长信息仍在收集中。
```

报告导出 PNG 必须包含新增质量区块，且不能破坏现有 html2canvas 导出逻辑。

## 7. JSON 导入导出与迁移

- 导出 JSON 自动包含新字段，不需要新增顶层 key。
- 导入旧备份时通过 `sanitizeRecord()` 补默认值。
- 导入新备份时：
  - `durationSeconds` 取较大的有效值；
  - `maxPositionSeconds` 取较大值；
  - `playCount` 取较大值或按明确的合并策略累加，必须在 UI 提示中保持一致；
  - `completed` 使用逻辑或；
  - `completedAt` 取最早的有效时间。
- 建议将 `SCHEMA_VERSION` 从 `1` 升到 `2`，在现有迁移入口中集中补字段。
- 不删除旧字段，不改变旧备份的可导入性。

7. 运行静态检查和真实 B 站浏览器验证。

## 10. 实现边界

- 不把累计观看秒数直接当成观看进度。
- 不用“打开次数”冒充“播放会话次数”；新功能使用 `playCount`。
- 不为补充总时长而增加批量接口请求。
- 不因为旧记录没有新字段而伪造完播结果。
- 不改变现有四个 Tab 的名称、数据隐私声明和本地存储定位。
