## 1. 现状核对与改动范围

项目是一个约 3200 行的**单文件用户脚本** `bilibili-watch-panel.user.js`，没有打包器和应用框架；仅依赖现有 Chart.js 与 html2canvas。v0.8 保持这一形态，不增加依赖、权限、页面外网络请求或服务器。

| 当前实现 | 具体位置/特点 | v0.8 接入点 |
| --- | --- | --- |
| `CONFIG.KEYS` | 记录、归档、提醒、按钮坐标、周目标等 key 已集中管理 | 加一个独立的界面设置 key |
| `Store` | `GM_getValue` 读记录时经 `sanitizeRecord` 过滤损坏条目 | 设置读取封装在此；健康检查必须读取原始 key，不能只调 `getRecords()` |
| `Panel.mount/bind/render` | Shadow DOM 里四个 Tab 与底部数据管理按钮 | 顶部设置入口；在同一 `.bwp-body` 切换设置视图 |
| `TOKENS_CSS` | 浅色变量；仍有图表、报告、提示及细部硬编码色值 | 深色变量覆盖 + 审查非变量色值 |
| `bindFabDrag/placeFab` | 按像素坐标保存 `fabPos`，`resize` 修正位置 | 尺寸变化重算边界；位置重置只删除此 key |
| `maybeShowWeeklyReminder` | 周日根据 `lastReminderWeek` 去重 | 显示前读提醒开关，关闭时撤掉已展示的 toast |
| `Panel.exportReport` | 在页面外克隆报告并用 html2canvas 导出白底图 | 固定导出用浅色报告样式，防主题污染 |

**注意现状**：`Store.clearAll()` 当前清理的是观看记录、归档、缓存和归档提示，不删 `fabPos`、周目标或提醒状态；v0.8 不借设置功能改变现有“清空数据”语义。`exportJSON()` 目前导出经 `Store.getRecords/getArchive` 清洗后的有效记录及周目标，不包含界面设置；v0.8 暂不改备份协议。

## 2. 设置数据模型

建议仅增加 `CONFIG.KEYS.UI_SETTINGS = 'uiSettings'`；与 schema v3 观看记录分开，**不升级观看记录 schema**。

```js
const DEFAULT_UI_SETTINGS = Object.freeze({
  theme: 'system',            // system | light | dark
  panelWidth: 380,           // CSS px：320..520，20 为步长
  fabSize: 48,              // 40 | 48 | 56
  weeklyReminder: true,
  shortcutEnabled: false,
});
```

| 场景 | 处理约定 |
| --- | --- |
| 新安装 / key 缺失 | 返回全套默认值，不立即写存储 |
| key 不是普通对象、值越界或类型错误 | 按字段恢复默认值；布尔值严格校验 `true/false`，不做字符串真假转换 |
| 宽度非法 | 限制在 320–520 范围并按 20 的步长取最近值；不存在 NaN/Infinity |
| 升级旧版本 | 保留旧 `fabPos`、周目标、观看记录；设置独立读取，不迁移数据 schema |
| 写入失败 | UI 回到实际读取值并提示保存失败，不给用户“已保存”的假象 |
| 恢复默认外观 | 只更新 `theme/panelWidth/fabSize` 三字段，删除 `fabPos`；保留提醒、快捷键、周目标 |

实现建议：`Store.getUiSettings()` 负责逐项验证；`Store.setUiSettings(partial)` 合并已验证值并保存，仅由设置变更调用。**不要**把 UI 设定塞进 `watchRecords`、`schemaVersion` 或 JSON 导入合并流程。

## 3. UI 状态与事件

```text
Panel.current        当前统计 Tab（继续仅四个值）
Panel.view           'stats' | 'settings'（运行时状态，不持久化）
Panel.open           面板开关（现有）
Panel.detailDrawer   记录详情（现有）
```

- 设置图标放在头部，使用真正的 `<button type="button">`、可见焦点态和 `aria-label`，不通过 Tab 列表伪造第五项。
- `Panel.showSettings()` 记住当前 Tab、展示设置页；`Panel.closeSettings()` 返回原 Tab，避免 `switchTab()` 在设置页时错误地渲染内容。
- `Panel.render()` 根据 `view` 分派到现有统计渲染或新增的 `renderSettings()`；检查弹出结果可放在设置内容里，无需新模态层。
- 进入设置、关闭设置和 Tab 切换时沿用 `destroyCharts()` 生命周期；不要给每次 render 重复绑定 document/window 级事件。
- `Esc` 事件明确按 `detailDrawer → settings → panel` 顺序处理。返回焦点：设置页关闭后回到设置按钮；快捷键打开后优先聚焦面板内可见控件，关闭后回到原先焦点（仍在文档内时）。
- `Alt+Shift+W` 的监听在 `Panel.bind()` 的单个 keydown 分支处理；`e.repeat/e.isComposing`、输入/可编辑元素和来自 Shadow DOM 的事件都要判定，避免热键打断文字输入；原有 Esc 分支不受设置开关控制。

### 响应式尺寸与重置

- 尺寸令牌例如 `--bwp-panel-width`、`--bwp-fab-size` 挂在宿主元素或 Shadow DOM 内的最外层，可由设置即时赋值；样式仅消费这两个变量。
- 面板使用 `width: var(--bwp-panel-width)` 与 `max-width: 96vw`；当视口比预设更窄时受视口约束，不把用户的预设值改写为更小值。
- 每次按钮尺寸变更后调用 `placeFab()` 重新夹取 x/y；重置时 `GM_deleteValue(CONFIG.KEYS.FAB_POS)`，用**当前视口宽度与实际按钮宽度**计算右侧位置，并保留安全边距。
- 对旧版 `{x,y}` 坐标保持读取兼容。测试视口变窄/缩放/重新加载；若需改为左右侧锚点，先独立定义迁移策略，避免无意改变已保存位置。

## 4. 主题方案

使用现有 `TOKENS_CSS` 作为单一来源：`:host` 默认浅色；`:host([data-theme="dark"])` 覆盖表面、边框、文字、输入、阴影和强调色。主题为 `system` 时，通过 `matchMedia('(prefers-color-scheme: dark)')` 解析出**当前生效主题**并更新宿主属性；系统切换时更新 UI。手动选择 light/dark 时忽略系统切换。避免同时维护一套完全重复的组件 CSS。

| 区域 | 检查点 |
| --- | --- |
| 基础组件 | 宿主、面板、页头、Tab、卡片、输入框、详情抽屉、footer、按钮的背景/文字/边框 |
| 图表 | Chart.js canvas 不会自动继承 CSS 字体色；切换主题时更新刻度、图例、网格/tooltip，销毁后按当前主题重建可见图表 |
| 悬浮元素 | 周日报告 toast、归档提示等非面板内元素也要以同样令牌渲染 |
| 固定白底导出 | `Panel.exportReport` 克隆用独立的浅色 token/样式和白色背景；不让当前 `data-theme` 或系统暗色影响 PNG |

先做颜色清单，分批替换**组件内的中性色硬编码**；保留功能性色和图表序列色，必要时只为对比度定义深色版本。不要盲目全局替换 `#fff`，导出图片必须继续白底。

## 5. 每周提醒与数据健康检查

### 5.1 提醒

`maybeShowWeeklyReminder()` 在任何修改 `lastReminderWeek` 之前读 `Store.getUiSettings().weeklyReminder`。关闭开关时查找并移除当前 `.bwp-toast`；已提醒周标记不清零，避免当周重复提醒。打开开关只改变设定，不主动立即补弹；下次满足周日进入条件才判断。

### 5.2 只读健康扫描

新增纯函数 `inspectRecordStorage(rawRecords, rawArchive, archiveNotice)`，由 UI 点击“开始检查”时调用。读取原始 `GM_getValue` 时逐项捕获异常；读取失败要给“未完成”状态；不能让 `Store.getRecords()` 的过滤掩盖无效条目。

建议结果形状（非存储 schema）：

```js
{
  status: 'ok' | 'issues' | 'incomplete',
  scannedAt: 0,
  counts: { records: 0, archive: 0 },
  findings: [
    { code: 'invalid-record', source: 'records', count: 0 }
  ]
}
```

判定细则：

1. 原始 key 不存在时等价于空数组；存在但非数组时为格式错误。
2. 遍历两数组，沿用 `isValidRecord` 作为最低要求；无效条目只累计，不进入重复索引。
3. 对有效条目使用 `date + '\0' + bvid` 作为键做跨主/归档分组；一组 2 条以上计 1 个重复组，涉及条数计整组长度。
4. 核查 `durationSeconds/maxPositionSeconds` 如果字段**存在**但为负、非有限、非数值则提示；旧记录缺字段不报错。`watchedSeconds` 无效已由最低要求捕获，不重复扣分。
5. `sessions` 缺失视为历史兼容；存在而非数组报告 1 条记录异常；数组内部逐条按 `sanitizeSession` 的起止条件判定。不要用累计播放秒数“推断”会话。
6. `archiveNotice.dropped > 0` 作为历史数据裁剪警告，不与当前无效条目相加。
7. UI 仅显示类别、数量、存储区，不渲染原始视频标题/URL/任意 HTML。检查不调用 `GM_setValue`/`GM_deleteValue`。

扫描最多处理现有上限的主数组与归档数组；若实际原始数据被外部写入为异常巨量数组，应有数量/时间保护并标记“扫描不完整”，而非阻塞页面。不要在 Collector 心跳里扫描。

## 6. 实施顺序与提交边界

| 阶段 | 改动 | 自检完成条件 |
| --- | --- | --- |
| A · 设置骨架 | 设置 key、验证、头部入口、设置视图 | 老数据原样读，设置重载后保持 |
| B · 外观 | 宽度、按钮尺寸、重置、主题及系统监听 | 缩放下按钮可见、四个 Tab 深色可读、PNG 保持白底 |
| C · 操作 | 提醒开关、快捷键、焦点及 Esc 顺序 | 编辑状态不触发热键，关闭提醒不留 toast |
| D · 健康 | 原始数据只读扫描及结果视图 | 坏数据能被发现，无数据写入 |
| E · 发布准备 | 测试回归、README/CHANGELOG/版本号 | 真实浏览器验收后再建 tag/Release |

每阶段可单独提交。未经用户明确要求，不把这三份设计文档自动视为 v0.8 已实现；不自动推送仓库或发布 Release。
