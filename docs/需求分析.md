# Bilibili Watch Panel · 需求分析

> 版本：0.1.0　|　阶段：阶段 0 · 需求分析
> 项目形态：Tampermonkey 用户脚本（单文件为主）
> 目标站点：bilibili.com 网页版
> 使用者：仅作者本人本地使用

---

## 1. 项目背景

作为 B 站的重度个人用户，平台的「历史记录」只告诉我"看过什么"，却回答不了我真正关心的问题：

- 我这一周到底在 B 站花了多少时间？
- 我把时间都花在了哪些 UP 主身上？
- 我通常什么时候打开 B 站？
- 我近期的观看习惯是在变多还是变少？

B 站官方不提供面向个人的、可离线查看的观看时长统计。本项目就是一个**纯本地、零上传**的浏览器用户脚本，把这件小事做掉。

**一句话定义**：一个装在自己浏览器里的、只读页面公开数据的 B 站个人观看数据面板。

## 2. 用户故事（User Stories）

> 格式：作为 B 站用户，我希望……以便……

| 编号 | 用户故事 | 对应功能 | 优先级 |
| --- | --- | --- | --- |
| US-01 | 作为 B 站用户，我希望插件**自动统计**我在每个视频上播放的时长，以便不用手动记账就能知道自己的真实观看时间 | 数据采集层 | MVP |
| US-02 | 作为 B 站用户，我希望在视频页有**不打扰观看**的入口，以便随时查看数据而不影响播放 | 浮动按钮 | MVP |
| US-03 | 作为 B 站用户，我希望点开面板就能看到**今日观看总时长、今日视频数**，以便快速了解"今天刷了多久" | 今日 Tab | MVP |
| US-04 | 作为 B 站用户，我希望看到**今日按 UP 主分布的饼图**，以便知道今天时间主要花在谁身上 | 今日 Tab | MVP |
| US-05 | 作为 B 站用户，我希望看到**近 7 天每天的观看时长折线**，以便观察自己的作息规律 | 本周 Tab | MVP |
| US-06 | 作为 B 站用户，我希望看到**近 7 天 Top5 UP 主柱状图**，以便回顾最近迷上了哪个 UP | 本周 Tab | MVP |
| US-07 | 作为 B 站用户，我希望查看**累计总时长、总视频数、覆盖 UP 主数**和最近的观看明细列表，以便做长期趋势回顾 | 全部 Tab | MVP |
| US-08 | 作为 B 站用户，我希望一键生成**本周使用报告**（卡片式、可导出图片），以便像"年度报告"一样留存自己的一周 | 报告 Tab | MVP |
| US-09 | 作为 B 站用户，我希望报告告诉我**本周最爱 UP 主 Top5** 和**观看高峰时段**，以便更有趣地总结自己的一周 | 报告 Tab | MVP |
| US-10 | 作为 B 站用户，我希望每周日打开 B 站时收到一次**轻提示**，以便不会忘记查看本周报告 | 周日提醒 | 加分 |
| US-11 | 作为 B 站用户，我希望可以**导出 JSON 备份**自己的数据，以便换电脑时迁移或自行存档 | 设置区 | MVP |
| US-12 | 作为 B 站用户，我希望可以**一键清空全部数据**（带二次确认），以便在不想记录时彻底删掉 | 设置区 | MVP |
| US-13 | 作为 B 站用户，我希望插件**绝不联网上传我的数据**，以便我的观看隐私不被泄露 | 隐私设计 | MVP |
| US-14 | 作为 B 站用户，我希望插件**不影响 B 站本身的播放和性能**，以便它作为一个安静的旁观者存在 | 非功能需求 | MVP |
| US-15 | 作为 B 站用户，我希望插件在**无数据时也能优雅展示空状态**，以便第一次安装不会看到报错 | UI 空状态 | MVP |
| US-16 | 作为 B 站用户，我希望插件可以**长期保存**数据（自动归档旧记录），以便长期使用不丢数据、不卡顿 | 存储层 | 加分 |

**数量**：16 条（满足"至少 8 条"要求）。

## 3. 功能需求清单

### 3.1 MVP 必须项

| 编号 | 功能 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| F-01 | 视频页识别 | 只在 `/video/` 页面激活采集 | 非视频页无采集日志、无额外请求 |
| F-02 | 视频信息解析 | 解析 bvid / 标题 / UP 主名 / UP 主 mid | 面板中标题、UP 主显示正确 |
| F-03 | 观看时长统计 | 5 秒心跳累加，暂停/切后台/关页面停止 | 与人工计时误差合理（±数秒/次） |
| F-04 | 同天同视频合并 | 同一天同一视频只保留一条记录，时长累加，次数 +1 | 重复打开同一视频后记录数不增加 |
| F-05 | 本地存储 | `GM_setValue('watchRecords', ...)` | 刷新页面数据仍在 |
| F-06 | 数据校验 | 写入/读取时过滤坏数据，不抛异常 | 人为写入脏数据后插件仍可运行 |
| F-07 | 悬浮按钮 | 48px 圆角方形按钮，B 站粉渐变，内联 SVG 图标，hover 抬升放大 | 任意 B 站页面均可点击开关、拖动吸附 |
| F-08 | 侧滑面板 | 右侧滑出，宽 380px，圆角 20px，0.32s 缓动动画 | 动画流畅，ESC 可关闭，≤480px 铺满 |
| F-09 | 今日 Tab | 总时长 / 视频数 / 较昨日 / 活跃记录时段 / 24 小时最近活跃时间线 / UP 主排行 / 今日记录 / 本周节奏 | 派生数据与本地记录一致 |
| F-10 | 本周 Tab | 近 7 天折线图 + Top5 柱状图 + 连续观看天数 + 环比上周 | 以周一为周起点 |
| F-11 | 全部 Tab | 累计总时长/视频数/UP 主数 + 近一年热力图 + 搜索 + 最多 100 条列表 | 列表按时间倒序 |
| F-12 | 报告 Tab | 卡片式周报 + 一句话总结 | 数据口径与周 Tab 一致 |
| F-13 | 报告导出 | 「导出图片」→ PNG 下载 | 生成图片内容完整 |
| F-14 | 数据导出 | 「导出JSON」按钮 | 下载 `watchRecords` 的完整 JSON |
| F-15 | 数据导入 | 「导入JSON」按钮 | 按「日期 + bvid」合并，重复取较大时长 |
| F-16 | 数据清空 | 「清空」+ 二次确认 | 确认后记录与归档全部清空 |
| F-17 | Shadow DOM 隔离 | 全部 UI 在 Shadow DOM 内 | 不与 B 站样式互相污染 |
| F-18 | 图表懒加载 | 面板打开时才渲染图表，关闭时销毁实例 | 反复开关无实例泄漏 |
| F-19 | 调试开关 | `debug` 开关控制控制台日志 | 关闭后无冗余日志 |
| F-20 | 选择器集中配置 | 所有选择器集中在 `SELECTORS` 常量区 | 单点修改即可适配改版 |
| F-21 | 错误隔离 | 采集/渲染主流程 try/catch 包裹 | 插件报错不影响 B 站页面 |

### 3.3 明确不做项（Out of Scope）

| 编号 | 不做的事 | 原因 |
| --- | --- | --- |
| N-01 | 不上传任何数据到服务器 | 隐私红线，项目定位就是纯本地 |
| N-02 | 不爬取、不存储他人用户数据 | 合规红线，只统计自己本机行为 |
| N-03 | 不破解、不绕过付费/会员机制 | 合规红线 |
| N-04 | 不批量调用 B 站接口抓取视频/用户信息 | 避免对平台造成压力，减少风险 |
| N-05 | 不修改 B 站任何业务数据（不代刷、不自动播放、不刷量） | 不干扰平台正常功能与计费体系 |
| N-06 | 不做账号体系、不做云同步、不做多人共享 | 超出个人本地工具定位 |
| N-07 | 不做移动端 / App 内嵌页适配 | 目标是网页版 Chrome/Edge |
| N-08 | 不做"刷视频时长排行""打卡作弊"类功能 | 违背统计工具的中立性 |
| N-09 | 不引入构建工具、npm 依赖、前端框架 | 单文件脚本便于安装与维护 |

## 4. 数据需求

### 4.1 需要记录的字段（watchRecords 单条记录）

| 字段 | 类型 | 含义 | 是否可空 |
| --- | --- | --- | --- |
| `id` | string | 记录唯一 ID（`date + '_' + bvid`） | 否 |
| `date` | string | 观看日期 `YYYY-MM-DD`（本地时区） | 否 |
| `videoId` | string | 视频 aid（数字串，页面存在时记录） | 是 |
| `videoTitle` | string | 视频标题 | 是 |
| `uploader` | string | UP 主昵称 | 是 |
| `uploaderId` | string | UP 主 mid | 是 |
| `bvid` | string | BV 号 | 否 |
| `timestamp` | number | 首次观看时间戳（ms） | 否 |
| `watchedSeconds` | number | 累计观看秒数 | 否 |
| `lastActive` | number | 最近一次活跃时间戳（ms） | 否 |
| `openCount` | number | 当天该视频被打开次数（合并用，默认 1） | 否 |

> 说明：`openCount` 是对原需求"观看次数单独按打开次数记"的落地字段；同一自然日、同一视频重复打开累加。

### 4.2 需要记录的辅助数据

| 数据项 | 存储 Key | 说明 |
| --- | --- | --- |
| 记录总量索引 | `watchRecords` | 主数组 |
| 归档记录 | `watchRecordsArchive` | 超过阈值后移出的旧记录 |
| 视频信息缓存 | `videoInfoCache` | 减少重复解析，带过期时间 |
| 调试开关 | `debug` | true / false |
| 周日提醒标记 | `lastReminderWeek` | 形如 `2026-W40`，防重复提醒 |
| 数据版本号 | `schemaVersion` | 用于未来数据迁移 |

### 4.3 明确**不记录**的字段（隐私边界）

| 不记录项 | 说明 |
| --- | --- |
| 任何账号凭证 / Cookie / Token | 绝不读取登录态 |
| 弹幕内容、评论内容 | 与观看统计无关 |
| 搜索历史、页面浏览轨迹 | 只关注视频页播放行为 |
| 他人用户数据合集 | 只记录自己看过的视频当天页面已公开显示的 UP 主名 |
| 精确位置、设备指纹 | 与需求无关 |
| 付费/会员内容购买信息 | 合规红线 |
| 视频完整播放进度 / 分 P 详细进度 | v0.1.0 不做，避免过度采集 |

## 5. 非功能需求

| 维度 | 要求 | 落地措施 |
| --- | --- | --- |
| **性能** | 不拖慢 B 站页面 | 心跳 5s 一次且只做轻量计算；面板关闭时不渲染图表；避免高频轮询 DOM |
| **性能** | 大量数据不卡顿 | 超过 5000 条自动归档；热力图先在 Stats 聚合再渲染；列表最多取 100 条；图表先聚合再绘制 |
| **兼容性** | Chrome + Edge + 篡改猴最新版 | 使用标准 ES2020 语法；`GM_*` API；Shadow DOM v1；无构建产物 |
| **兼容性** | B 站改版可快速修复 | 所有选择器集中在 `SELECTORS` 常量区；信息获取多级降级 |
| **隐私** | 数据只存本地，绝不上传 | 全部走 `GM_setValue/GM_getValue`；代码中不存在数据上报端点 |
| **隐私** | 可控可清除 | 提供"导出JSON""导入JSON"与"清空"入口 |
| **合规** | 只读页面已公开加载的数据 | 不批量爬取、不破解、不碰付费内容、不干扰播放与计费 |
| **可靠性** | 插件出错不影响 B 站 | 采集/渲染主流程 try/catch；写入前校验；坏数据跳过 |
| **可维护性** | 单文件但结构清晰 | 模块化注释分区：配置 / 工具 / 存储 / 采集 / 统计 / UI / 报告 |
| **可观测性** | 便于自查 | 统一 `log()` 输出，受 `debug` 开关控制 |

## 6. 风险与对策

| 编号 | 风险 | 影响 | 对策 |
| --- | --- | --- | --- |
| R-01 | B 站改版导致选择器失效 | 标题/UP 主解析失败 | 选择器集中在 `SELECTORS`；多级降级解析；解析失败用 bvid 兜底，不影响计时 |
| R-02 | 播放器结构变化，检测不到播放状态 | 时长统计不准 | 以 `<video>.currentTime` 实际推进为可信来源；找不到元素时静默跳过 |
| R-03 | 数据量不断增长 | 存储变慢、面板卡顿 | 超过 5000 条自动归档；图表聚合后绘制 |
| R-04 | GM 存储被清空 / 隐私模式 | 数据丢失 | 提供 JSON 导出备份；文档说明存储位置与风险 |
| R-05 | 跨零点观看 | 时长归属错误 | 以心跳触发时刻的本地日期归天；跨零点按边界拆分 |
| R-06 | 切后台计时不准 | 虚增时长 | 监听 `visibilitychange`，切后台立即停止计时 |
| R-07 | 多标签页同开同一视频 | 记录互相覆盖 | 写入前重新 `GM_getValue` 再合并（读改写）；极端并发以最后写入为准并在文档说明 |
| R-08 | 倍速播放导致口径争议 | 统计口径不统一 | 明确统计**实际停留墙钟秒数**，不乘倍速；文档写明 |
| R-09 | 自动化测试缺失 | 回归风险 | 提供 `docs/测试清单.md` 手工自测表 + 代码静态走查 |
| R-10 | 推送包含无关文件 | 隐私泄露 | `.gitignore` 忽略 `.env`/`*.local`/日志；提交前自查；README 声明仓库不含观看数据 |
| R-11 | CDN 依赖不可用 | 图表/导出失败 | `@require` 走主流 CDN；运行时检测全局变量，缺失时降级提示 |
| R-12 | 篡改猴权限收紧 | `GM_*` 不可用 | 元数据显式声明 `@grant`；文档标注需最新版篡改猴 |

## 7. 默认决策（无需等待确认）

| 决策项 | 默认选择 | 理由 |
| --- | --- | --- |
| 统计口径 | 实际播放墙钟秒数（不乘倍速） | 最贴近"我花了多少时间"的直觉 |
| 心跳间隔 | 5 秒 | 精度与性能的平衡 |
| 周起点 | 周一 | 符合国内习惯 |
| 每天记录维度 | 同一天同一视频合并为一条 | 控制数据量 |
| 存储位置 | `GM_setValue` | 隐私、跨页面可用、无需额外权限弹窗 |
| 图表库 | Chart.js | 轻量、稳定、文档好 |
| 导出图片 | html2canvas | 成熟、单文件引入 |
| 面板宽度 | 380px | 够放图表，不遮挡主要播放区 |
| 归档阈值 | 5000 条 | 兼顾性能与保留时长 |
| 时区处理 | 浏览器本地时区 | 使用者在中国，与 B 站一致 |
