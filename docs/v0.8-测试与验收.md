## 1. 测试原则与记录格式

测试目标：设置能保存且可恢复、主题在真实页面可读、按钮不会因缩放丢失、健康检查只读、v0.7.1 的采集与导出行为不回归。优先在 Chrome + Tampermonkey 完整走查，再用 Edge 对安装、缩放、主题、快捷键做交叉验证。

| 字段 | 记录方式 |
| --- | --- |
| 结果 | `待测 / 通过 / 失败 / 阻塞`；计划阶段一律为待测 |
| 证据 | 浏览器版本、脚本版本、页面路径、操作步骤、截图/控制台输出或下载文件 |
| 数据保护 | 用测试浏览器配置或先导出真实数据；破坏性测试只在测试环境执行 |
| 失败判定 | 不以“看起来没报错”代替数据、键盘、下载文件和存储内容检查 |

测试页面至少覆盖 `www.bilibili.com/`、`www.bilibili.com/video/BV...`、一个 SPA 跳转后的页面。记录实际浏览器与 Tampermonkey 版本；测试时不要将个人观看记录附入仓库。

## 5. 执行顺序与发布门槛

1. 使用**测试配置文件**制造空数据、旧 schema、非法设置、损坏记录；测试前备份真实 JSON，不把个人数据提交仓库。
2. 静态检查和小范围逻辑测试先行，再真实浏览器手测交互、缩放、系统主题和下载文件。
3. 记录失败的复现环境、截图与修复提交；每次修复后重测对应功能及 RG-01～RG-06。
4. 所有 P0/P1 项及回归项通过，无法覆盖项明确记录原因、风险与人工确认。不得把“待测”改成“通过”以凑齐发布条件。
5. 完成 README、CHANGELOG 与安装说明，确保 `@version 0.8.0` 与发布内容一致；用户确认后再提交/推送/创建 `v0.8.0` Release。

**记录建议**：执行时在每条用例状态后附 `日期 + 浏览器版本 + 证据路径/问题编号`。本文件只提供计划，不包含任何已执行测试结论。
