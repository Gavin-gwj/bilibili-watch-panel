> 版本：0.1.0　|　阶段：阶段 1 · 技术方案设计

## 1. 整体架构

### 1.1 架构图（文字版）

```
┌──────────────────────────────────────────────────────────────┐
│                      Bilibili 网页（/video/）                 │
│  <video> 元素 · 页面 __INITIAL_STATE__ · DOM 元信息 · URL      │
└──────────────────────────────┬───────────────────────────────┘
                               │ 只读页面已公开加载的数据
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ ① 事件采集层  Collector                                      │
│   · 页面判断：仅 /video/ 路径                                 │
│   · 视频信息解析（URL → __INITIAL_STATE__ → DOM 降级）        │
│   · 5s 心跳：video.currentTime 实际推进才累加                 │
│   · 暂停 / 切后台 / 页面关闭 → 立即结算                       │
│   · 同天同视频合并、观看次数 +1                               │
└──────────────────────────────┬───────────────────────────────┘
                               │ 原始记录（已校验）
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ ② 数据处理层  Core                                          │
│   · 数据校验 sanitizeRecord                                 │
│   · 跨零点拆分 splitAcrossMidnight                          │
│   · 归档 archiveIfNeeded（> 5000 条）                        │
│   · 聚合 aggregateByDay / aggregateByUploader / timeSlot     │
└──────────────────────────────┬───────────────────────────────┘
                               │ 结构化数据
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ ③ 存储层  Store                                             │
│   · watchRecords（主数组）                                   │
│   · watchRecordsArchive（归档）                              │
│   · videoInfoCache（视频信息缓存）                            │
│   · debug / schemaVersion / lastReminderWeek                 │
│   · 全部通过 GM_setValue / GM_getValue，仅本地               │
└──────────────────────────────┬───────────────────────────────┘
                               │ 读取聚合结果
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ ④ UI 展示层  Panel                                          │
│   · 右上角浮动按钮（Shadow DOM 挂载点）                       │
│   · 右侧滑出面板 380px，4 个 Tab：今日 / 本周 / 全部 / 报告   │
│   · Chart.js 图表（懒加载，关闭即 destroy）                   │
│   · html2canvas 报告导出 PNG                                 │
│   · 设置区：导出 JSON / 清空全部数据                          │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 数据流

```
页面加载 → 判断是否 /video/ → 解析视频信息
   → 注入视频页 UI（浮动按钮）
   → 启动 5s 心跳（仅视频元素在播放时累加）
   → 定时合并写入 GM_setValue('watchRecords')
   → 用户打开面板 → 从存储读取 → 聚合 → 懒渲染图表
   → 用户导出 / 清空 → 文件下载 / 二次确认
```

### 1.3 关键设计原则

| 原则 | 说明 |
| --- | --- |
| 只读采集 | 只读取页面已公开加载的数据，不主动批量请求接口 |
| 失败隔离 | 采集与渲染主流程 try/catch；任何失败不影响 B 站本身 |
| 单一可信来源 | 时长只信 `<video>.currentTime` 的推进，不信播放器 UI 状态类名 |
| 选择器集中 | 所有 DOM 选择器统一在 `SELECTORS` 常量区，便于改版修复 |
| UI 隔离 | 全部 UI 放在 Shadow DOM，杜绝与 B 站样式互相污染 |
| 存储自愈 | 读取时结构校验，坏数据跳过，不抛异常 |
| 懒加载 | 图表只在面板打开对应 Tab 时创建，关闭/切换时销毁 |

## 2. 数据模型定义

### 2.1 主记录 watchRecords

```js
/**
 * @typedef {Object} WatchRecord
 * @property {string} id            记录唯一 ID，格式 `${date}_${bvid}`
 * @property {string} date          观看日期 YYYY-MM-DD（浏览器本地时区）
 * @property {string} videoId        视频 aid（数字串，可空）
 * @property {string} videoTitle     视频标题（可空）
 * @property {string} uploader       UP 主昵称（可空）
 * @property {string} uploaderId     UP 主 mid（可空）
 * @property {string} bvid           BV 号（必需）
 * @property {number} timestamp     首次观看时间戳（ms）
 * @property {number} watchedSeconds 累计观看秒数（墙钟秒，不乘倍速）
 * @property {number} lastActive    最近一次活跃时间戳（ms）
 */
```

### 2.2 记录示例

```js
{
  id: "2026-10-02_BV1xx411c7mD",
  date: "2026-10-02",
  videoId: "113456789012345",
  videoTitle: "【示例】一个视频标题",
  uploader: "示例UP主",
  uploaderId: "12345678",
  bvid: "BV1xx411c7mD",
  timestamp: 1759392000000,
  watchedSeconds: 183,
  lastActive: 1759392183000
}
```

### 2.3 辅助存储模型

| Key | 类型 | 说明 |
| --- | --- | --- |
| `watchRecords` | `WatchRecord[]` | 主记录数组，按 `lastActive` 倒序维护 |
| `watchRecordsArchive` | `WatchRecord[]` | 超过 5000 条后移出的旧记录 |
| `videoInfoCache` | `Object<string, {title, uploader, uploaderId, videoId, expireAt}>` | 视频信息缓存，默认 7 天过期 |
| `debug` | `boolean` | 控制台日志开关 |
| `schemaVersion` | `number` | 数据版本号，当前 `1` |
| `lastReminderWeek` | `string` | 形如 `2026-W40`，防重复提醒 |

### 2.4 观看次数口径

`watchRecords` 按「天 + 视频」合并，因此主数组里没有独立的「次数」字段。为满足"观看次数单独按打开次数记"，在记录中扩展一个可选字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `openCount` | `number` | 当天该视频被打开的次数，默认 1；同一视频重复打开累加 |

> 该字段是对需求文档中数据模型的可兼容扩展，旧记录缺失时按 1 处理。

## 3. 数据采集方案

### 3.1 激活条件

| 条件 | 行为 |
| --- | --- |
| `location.pathname` 以 `/video/` 开头 | 启用采集 + 注入 UI |
| 其他页面（首页、动态、番剧、直播等） | 仅安装脚本，不采集、不注入、不请求 |

### 3.2 视频信息获取（三级降级）

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | `window.__INITIAL_STATE__` | B 站页面自带数据，最准确；读取 `videoData` / `upData` |
| 2 | DOM 元信息 | 通过 `SELECTORS` 中的选择器读取标题与 UP 主 |
| 3 | URL + document.title | 兜底：从 `/video/BV...` 解析 bvid，标题用 `document.title` 清洗 |

**约束**：不额外批量请求；最多允许一次视频信息 API（仅当三级降级都拿不到标题/UP 主时触发），且结果写入 `videoInfoCache` 缓存，7 天内不重复请求。

### 3.3 时长统计（5 秒心跳）

```
每 5s tick：
  if (页面不可见 document.hidden) return
  if (video.paused || video.ended) return
  if (video.currentTime 与上次相比没有推进) return   // 卡顿/加载中不计
  watchedSeconds += 实际推进的墙钟秒数（上限 = 心跳间隔）
  videoInfoCache 合并写入本地
```

| 事件 | 处理 |
| --- | --- |
| `play` | 重置 `lastTickTime`，开始允许累加 |
| `pause` / `ended` | 立即结算并保存一次 |
| `visibilitychange` → hidden | 立即结算并保存，停止累加 |
| `beforeunload` / `pagehide` | 最终结算并保存 |
| `seeking` / `waiting` | 标记暂停累加，避免卡顿时虚计 |
| `/video/` 内 SPA 切换视频 | 监听 URL 变化，重建当前视频会话 |

### 3.4 跨零点

| 场景 | 处理 |
| --- | --- |
| 单次心跳跨过 00:00 | 按时间比例/边界拆分到两天，最多在两天各记一条 |
| 合并规则 | 拆分后的每条记录仍按 `date + bvid` 合并 |

### 3.5 去重与合并

| 规则 | 说明 |
| --- | --- |
| 主键 | `id = ${date}_${bvid}` |
| 同天同视频 | 不新建记录，`watchedSeconds` 累加，`openCount + 1`，更新 `lastActive` |
| 新的一天 | 新建独立记录，与昨天互不影响 |
| 写入方式 | 读改写：每次写入前 `GM_getValue` 重新取最新主数组，避免多标签覆盖 |

## 4. 存储方案

### 4.1 存储 API

| API | 用途 |
| --- | --- |
| `GM_setValue` | 写入主记录、归档、缓存、开关 |
| `GM_getValue` | 读取上述数据 |
| `GM_deleteValue` | 清空数据 / 清除缓存 |

统一通过 `Store` 模块访问，禁止在业务代码里散落 `GM_*` 调用。

### 4.2 容量控制与归档

| 阈值 | 行为 |
| --- | --- |
| `watchRecords.length > 5000` | 按 `lastActive` 排序，保留最新 3000 条为主数组，其余追加到 `watchRecordsArchive` |
| `watchRecordsArchive.length > 20000` | 仅保留最新 20000 条，防止无限膨胀 |
| 面板查询 | 默认查询主数组；「全部」Tab 统计时合并归档数据 |

### 4.3 数据迁移

| 版本 | 迁移动作 |
| --- | --- |
| v1（0.1.0） | 初始结构；读取时校验字段类型，坏数据丢弃并计数 |

未来如字段变更，按 `schemaVersion` 递增，在 `migrate()` 中做一次性转换，迁移失败保留原数据并记录日志。

### 4.4 结构校验规则

```js
function isValidRecord(r) {
  return r && typeof r === 'object'
    && typeof r.id === 'string' && r.id.length > 0
    && typeof r.date === 'string' && /^\d{4}-\d{2}-\d{2}$/.test(r.date)
    && typeof r.bvid === 'string' && r.bvid.length > 0
    && Number.isFinite(r.watchedSeconds) && r.watchedSeconds >= 0
    && Number.isFinite(r.timestamp)
    && Number.isFinite(r.lastActive);
}
```

## 5. UI 方案

### 5.1 结构

```
Shadow DOM（宿主：<div id="bwp-host">）
├── 浮动按钮 .bwp-fab（右上角，圆角方形 48px，渐变粉，内联 SVG 图标，hover scale 1.06）
└── 侧滑面板 .bwp-panel（右侧，宽 380px，圆角 20px，多层柔和阴影，0.32s）
    ├── Header：品牌标识（Logo + 标题 + 隐私副标题）+ 关闭按钮
    ├── Tab 栏：分段式胶囊容器：今日 / 本周 / 全部 / 报告
    ├── 内容区 .bwp-body
    │   ├── 今日：数字卡 ×2 + 环形图 canvas
    │   ├── 本周：数字卡 ×3（总时长 / 连续观看 / 环比上周）+ 折线图 canvas + 柱状图 canvas
    │   ├── 全部：数字卡 ×3 + 归档提示条 + 近一年热力图 + 搜索框 + 最多 100 条列表
    │   └── 报告：卡片式周报（大数字卡 ×3 含环比）+ 导出图片按钮
    └── Footer 设置区：导出JSON / 导入JSON / 清空
```

### 5.1.1 视觉规范（v0.2.0）

| 维度 | 规范 |
| --- | --- |
| 主色 | 品牌粉 `#fb7299`，渐变区间 `#ff8fb1 → #fb7299 → #e8578a` |
| 中性色 | 标题 `#18191c`、正文 `#61666d`、次要 `#9499a0`、描边 `#f0f1f3` |
| 圆角 | 面板 20px / 卡片与图表 15px / 控件 10–13px / 胶囊 999px |
| 间距 | 内容区 16px 内边距，卡片间 10px，区块间 14–16px |
| 阴影 | 面板 `-10px 0 40px rgba(97,102,109,.16)`；卡片 `0 4px 14px rgba(251,114,153,.08)` |
| 字体 | 系统字体栈（PingFang SC → Microsoft YaHei），数字 21px/700，正文 12.5px |
| 图标 | 统一内联 SVG（线性、圆角端点），不使用 emoji |
| 交互态 | hover / active / focus-visible 全量覆盖，`prefers-reduced-motion` 降级动效 |
| 响应式 | ≤480px 面板铺满视口宽度 |

### 5.2 交互

| 交互 | 行为 |
| --- | --- |
| 点击浮动按钮 | 面板开/关切换 |
| 点击面板关闭按钮 | 关闭面板 |
| 按 `Esc` | 关闭面板 |
| 点击 Tab | 切换内容并按需懒渲染图表 |
| 关闭面板 | 销毁所有 Chart 实例，清空 canvas 引用 |
| 拖动 | 按住浮动按钮拖动，松手吸附左右边缘，位置经 `fabPos` 持久化 |
| 键盘 | Tab 键可在按钮/Tab/关闭/底部操作间移动，焦点有可见描边 |

### 5.3 样式隔离

- 使用 `attachShadow({ mode: 'open' })`。
- 所有样式写在 Shadow DOM 内的 `<style>`（v0.3.0 已移除未使用的 `GM_addStyle` 权限声明）。
- 样式以「设计令牌 + 组件类」组织，集中在 `PANEL_HTML` / `REPORT_CSS` / `TOAST_CSS` 三处，便于整体换肤。
- 色值统一取自 5.1.1 视觉规范，不在组件内引入杂色。

### 5.4 动效

| 动效 | 对象 | 参数 |
| --- | --- | --- |
| 卡片错峰入场 | 数字卡、图表容器、记录列表 | `bwp-rise` 位移 9px + 轻微缩放，360ms，`cubic-bezier(.22,.9,.3,1)` |
| 错峰间隔 | 同级元素 | 每个索引 +46ms（`--bwp-i`），列表封顶 8 档避免长列表拖沓 |
| 报告区块 | 报告头 / 大数字卡 / 各区块 / 总结 | 按 0–6 顺序依次入场 |
| 进度条生长 | 报告 Top5 占比条 | `scaleX(0→1)`，520ms，按条目 160/230/300ms 错峰 |
| 空状态图标 | 无数据插画位 | 400ms 入场 |

**约束**

- 一律使用 `animation-fill-mode: backwards`，动画结束后不残留内联样式，交还 `hover` 控制权。
- `prefers-reduced-motion: reduce` 时全部动画关闭。
- 导出 PNG 前，`exportReport` 会清空克隆体上的 `animation/transition/opacity/transform`，避免 html2canvas 重启动画导致截图停在起始帧。
- 仅入场动画，不做滚动触发，避免面板内滚动时反复重播。

### 5.5 空状态

无数据时各 Tab 显示统一空状态：粉色圆角图标位（内联 SVG）+ 文案，不渲染空图表，避免 Chart.js 报错。

## 7. 技术选型表

| 项目 | 选什么 | 为什么 | 备选方案 |
| --- | --- | --- | --- |
| 运行形态 | Tampermonkey 单文件用户脚本 | 安装最简单，符合"只用自己本地"定位 | Chrome 扩展（需打包、上架/开发者模式） |
| 语言 | 原生 JavaScript（ES2020） | 无构建、无依赖、篡改猴直接运行 | TypeScript（需构建，超出约束） |
| UI 隔离 | Shadow DOM | 原生、无库、样式彻底隔离 | iframe（通信复杂）、CSS 前缀（易冲突） |
| 存储 | `GM_setValue/GM_getValue` | 跨页面持久、仅本地、无需服务器 | localStorage（分域、可能被清）、IndexedDB（复杂度高） |
| 图表 | Chart.js（@require CDN） | 轻量、成熟、CDN 稳定、API 简单 | ECharts（体积大）、手写 SVG（工作量大） |
| 图片导出 | html2canvas（@require CDN） | 成熟、对 Shadow DOM 场景可配合临时容器使用 | 手写 Canvas 绘制（复杂） |
| 视频信息 | 页面 `__INITIAL_STATE__` + DOM + URL 降级 | 零额外请求，最稳 | 调用视频信息 API（有请求，仅兜底一次并缓存） |
| 时长来源 | `<video>.currentTime` 推进 | 唯一可信，不受播放器 UI 改版影响 | 监听播放器自定义事件（易失效） |
| 数据聚合 | 纯 JS reduce / Map | 无依赖、数据量可控 | lodash（不必要） |
| 下载文件 | Blob + `URL.createObjectURL` | 原生、无依赖 | `GM_download`（需额外权限） |
| 版本管理 | Git + GitHub（公开仓库） | 便于备份与迭代 | 仅本地 Git（无远程备份） |
| 提交规范 | Conventional Commits | 历史清晰可检索 | 自由格式（不可追溯） |
