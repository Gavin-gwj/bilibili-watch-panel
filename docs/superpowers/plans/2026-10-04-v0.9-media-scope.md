# v0.9 采集范围扩展与分 P 识别 · 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Bilibili Watch Panel 正确统计番剧、课程与多 P 视频，并把唯一键升级为 `mediaKey`（schema v4）。

**Architecture:** 单文件用户脚本内新增「媒体解析分派层」：按 URL 判定页面类型，分别从 `__INITIAL_STATE__`、`playurlSSRData`、`__EduPlayPiniaState__` 读取元信息，统一产出含 `mediaKey` 的 info 对象；存储层通过 `sanitizeRecord` 补齐 v4 字段，保持旧数据可读。

**Tech Stack:** 原生 JavaScript（ES2020）、Shadow DOM、GM_setValue/GM_getValue、Chart.js 4.4.1、html2canvas 1.4.1；测试用 Node 标准库 `assert` + `vm` 与 Playwright CLI。

**Spec:** `docs/superpowers/specs/2026-10-04-v0.9-media-scope-design.md`

## Global Constraints

- 不引入 React / Vue / Tailwind / 构建工具 / npm 依赖。
- 不新增服务器、不上传观看数据、不新增批量 API 请求。
- 不新增 `@grant` / `@require` / `@match` 声明。
- schema 升级到 v4，必须向后兼容 v3 记录与旧 JSON 备份。
- 保留四个 Tab 名称与信息架构。
- 时长口径沿用 v0.8.2：只在播放进度真实推进时按墙钟秒数累计。
- 每个任务结束后运行 `node --check bilibili-watch-panel.user.js` 与 `node tests/v0.8.test.cjs`。

**Interfaces:**
- Produces: `CONFIG.SCHEMA_VERSION === 4`；`CONFIG.MEDIA_TYPE`；`buildMediaKey(info)` 返回 string；`sanitizeRecord(r)` 输出含 `mediaKey/mediaType/page/partTitle/seasonTitle`。

- [ ] **Step 1: 写失败测试**

```js
test('v3 旧记录迁移到 v4 且数值不变', () => {
  const out = sanitizeRecord(record({ bvid: 'BV1xx', watchedSeconds: 60 }));
  assert.equal(out.mediaKey, 'BV1xx');
  assert.equal(out.mediaType, 'video');
  assert.equal(out.page, 1);
  assert.equal(out.watchedSeconds, 60);
});
test('多 P 与番剧课程 mediaKey 规则', () => {

  assert.equal(buildMediaKey({ mediaType: 'video', bvid: 'BV1xx', page: 2, pageCount: 3 }), 'BV1xx_p2');
  assert.equal(buildMediaKey({ mediaType: 'bangumi', epId: '321808' }), 'ep321808');

});
```
