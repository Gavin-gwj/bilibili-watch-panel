# v0.9 采集范围扩展与分 P 识别 · 设计规格

> 版本：v0.9.0　|　基线：v0.8.2　|　日期：2026-10-04
> 状态：已按用户确认的方案实现（用户明确要求「按推荐来，完成后直接推送并发布」）

## 1. 背景与问题

当前采集入口只有 `/^\/video\//` 一条判断，导致三类观看行为无法被正确统计：

| 场景 | 现状 | 影响 |
| --- | --- | --- |
| 番剧 `/bangumi/play/ep*` | 完全不采集 | 番剧时长从统计中消失 |
| 课程 `/cheese/play/ep*` | 完全不采集 | 课程时长从统计中消失 |
| 多 P 视频 | 同 `date + bvid` 合并为一条 | 各分 P 进度、完播率互相污染 |

v0.9.0 解决以上三项，并把唯一键从 `bvid` 升级为 `mediaKey`。

## 2. 已核实的页面数据结构

以下结构通过抓取真实页面 HTML 核实，不是推测。

### 2.1 普通视频页 `/video/BV*`

`window.__INITIAL_STATE__`（JSON）：

- `videoData.bvid` / `aid` / `title` / `duration` / `tname`
- `videoData.videos`：分 P 数量
- `videoData.pages[]`：每项含 `page`、`part`、`duration`、`cid`
- `upData.mid` / `name`
- 顶层 `p`：当前分 P 序号

### 2.2 番剧页 `/bangumi/play/ep*`

无 `__INITIAL_STATE__`，数据在 `const playurlSSRData = {...}` 内联脚本中：

- `data.result.video_info.timelength`（毫秒）与 `video_info.dash.duration`（秒）
- `data.result.arc.bvid` / `aid` / `cid`
- `data.result.supplement.ogv_episode_info.episode_id` / `index_title` / `long_title`
- `data.result.supplement.ogv_season_info.season_id`
- 页面 `<title>`：`名侦探柯南第1集-番剧-...`

运行时同时存在 `window.__PLAYURL_HYDRATE_DATA__`。

### 2.3 课程页 `/cheese/play/ep*`

数据在 `window.__EduPlayPiniaState__`（JSON **字符串**）：

- `index.viewInfo.title`（课程名）、`season_id`、`up_info.mid` / `uname`
- `index.currentEp`：`id`(ep_id)、`aid`、`cid`、`duration`(秒)、`title`、`index`
- `index.epList[]`：全部课时

## 3. 数据模型（schema v4）

记录新增字段，全部向后兼容：

| 字段 | 类型 | 含义 | 旧记录迁移值 |
| --- | --- | --- | --- |
| `mediaKey` | string | 当日唯一键 | `bvid` |
| `mediaType` | `video`\|`bangumi`\|`cheese` | 媒体类型 | `video` |
| `page` | number | 分 P / 剧集序号，1 起 | `1` |
| `partTitle` | string | 分 P 标题 / 剧集标题 | `''` |
| `seasonTitle` | string | 番剧名 / 课程名 | `''` |

`bvid` 保留但允许为空（课程页没有 bvid）。

### 3.1 mediaKey 规则

| 场景 | mediaKey | 说明 |
| --- | --- | --- |
| 单 P 视频 | `BV1xx...` | 与旧 `bvid` 完全一致，保证旧记录可继续合并 |
| 多 P 视频 | `BV1xx..._p2` | 用 `pages.length > 1` 判断 |
| 番剧 | `ep321808` | 用 ep_id |
| 课程 | `cheese_ep1209625` | 加前缀避免与番剧 ep 号冲突 |

### 3.2 迁移策略

- 读取时由 `sanitizeRecord()` 补齐字段，**不重写**用户已存数据。
- `isValidRecord` 的必需字段从 `bvid` 改为 `mediaKey || bvid`，旧记录仍合法。
- `schemaVersion` 升为 `4`；旧 JSON 备份导入时同样走 `sanitizeRecord`。
- 去重索引从 `date + bvid` 统一改为 `date + mediaKey`。

## 4. 采集口径（用户已确认）

| 决策 | 取值 |
| --- | --- |
| 番剧 / 课程是否计入总时长 | 计入，列表用类型标签区分 |
| 分 P 是否分条 | 每个分 P 独立一条，进度与完播各自计算 |
| 直播 | 不采集（无播放进度，口径不匹配） |

## 5. 实现边界

### 5.1 涉及改动

- `SELECTORS`：新增番剧、课程页选择器兜底
- `Collector.isVideoPage()` → 支持三类播放页
- 新增 `resolveMediaInfo()`：按页面类型分派解析
- 新增 `parseCheeseState()` / `parseBangumiHydrate()` / 扩展 `readInitialState()`
- `findRecordIndex()`、`applySeconds()`、`recordOpen()` 改用 `mediaKey`
- `Stats` 聚合：`distinctVideoCount` 等按 `mediaKey` 去重
- 记录列表与详情抽屉：显示 `partTitle` / `seasonTitle` 与类型标签
- 版本号、README、CHANGELOG、测试清单

### 5.2 明确不改

- 不新增权限、不新增外部请求、不新增依赖
- 不改变时长计时口径（v0.8.2 的墙钟秒数）
- 不改变四个 Tab 的信息架构
- 不采集直播

## 7. 验收标准

| 编号 | 标准 |
| --- | --- |
| A-01 | 旧 v3 记录读取后自动补齐 v4 字段，数值不变 |
| A-02 | 单 P 视频的 `mediaKey` 等于旧 `bvid`，历史合并结果不变 |
| A-03 | 多 P 视频每个分 P 独立记录，进度与完播互不影响 |
| A-04 | 番剧页播放后写入 `mediaType='bangumi'` 的记录 |
| A-05 | 课程页播放后写入 `mediaType='cheese'` 的记录 |

## 8. 已知限制

- 番剧 / 课程页的真实播放器回归需在浏览器手动确认；本轮以真实页面结构解析 + 隔离页断言覆盖。
- 课程页 `playable:false` 的付费课时无法播放，自然也不会产生记录，这是预期行为。
