## 1. 项目概况

Bilibili Watch Panel 是一个纯本地运行的 B 站观看数据面板，使用原生 JavaScript、Shadow DOM、`GM_getValue/GM_setValue`、Chart.js 和 html2canvas。

核心目标：

- 统计本人在 B 站视频页的观看行为。
- 提供今日、本周、全部、报告四个数据视图。
- 分析观看时长、视频数量、观看进度、完播率和重复观看。
- 所有数据保存在本机 Tampermonkey 存储，不上传观看数据。

GitHub 仓库：<https://github.com/Gavin-gwj/bilibili-watch-panel>

当前已发布 Release：`v0.1.0`、`v0.2.0`、`v0.2.1`、`v0.3.0`、`v0.3.1`、`v0.4.0`、`v0.5.0`、`v0.6.0`、`v0.7.0`、`v0.7.1`。

## 3. 已完成功能

### 3.1 采集和存储

- 仅在 `/video/` 路径采集。
- 通过 URL、`__INITIAL_STATE__`、DOM 三级降级解析视频信息。
- 使用 `<video>.currentTime` 的实际推进量累计观看秒数。
- 暂停、卡顿、切后台、切换视频、页面关闭时停止或结算。
- 同一天同一视频按 `date + bvid` 合并。
- 主记录超过 5000 条后归档，归档上限 20000 条。
- JSON 导出和导入合并可用。

### 3.2 观看质量分析

schema 已升级到 `3`，记录新增字段：

```js
{
  durationSeconds: 1260,
  maxPositionSeconds: 1040,
  playCount: 3,
  completed: false,
  completedAt: 0,
  sessions: []
}
```

字段语义：

- `durationSeconds`：最近一次读取到的有效视频总时长。
- `maxPositionSeconds`：当天记录达到过的最高播放位置。
- `playCount`：有效播放会话次数，不等同于打开次数。
- `completed`：是否达到完播判定。
- `completedAt`：第一次达到完播判定的时间戳。
- `openCount`：保留原语义，表示当天打开次数。
- `sessions`：已结束播放会话数组，记录开始/结束时间、会话内观看秒数、暂停/后台/跳转次数和结束原因；旧记录为空数组，不推断历史会话。

`Stats` 已提供：

```js
Stats.recordProgress(record)
Stats.completionRate(records)
Stats.averageVideoDuration(records)
Stats.repeatWatchCount(records)
Stats.sessionStats(records)
Stats.quality(records, options)
```

统计规则：

- 观看进度：`min(1, maxPositionSeconds / durationSeconds)`。
- 无总时长记录不进入完播率分母，但继续进入观看时长统计。
- 重复观看次数：`max(0, playCount - 1)`。
- 全部数据按 `bvid` 去重时，观看秒数累加、最高位置取最大值、完播状态逻辑或。

### 3.3 当前 UI

- 右上角 48px 浮动按钮。
- 右侧 380px 抽屉面板。
- 四个 Tab：今日 / 本周 / 全部 / 报告。
- Shadow DOM 样式隔离。
- Chart.js 图表按 Tab 懒加载，关闭面板时销毁。
- 今日、本周、全部、报告已加入观看质量摘要。
- 全部 Tab 已支持：全部 / 已完播 / 未完播 / 进度未知筛选。
- 报告支持 html2canvas 导出 PNG。
- 支持 `prefers-reduced-motion`。

## 4. 当前界面问题

现有界面已经可用，但需要向更现代的“个人数据工作台”方向优化。

### 4.1 视觉问题

- 粉色背景、粉色阴影和粉色边框使用面积偏大，视觉层级不够清晰。
- 卡片数量较多，部分区域存在“卡片套卡片”的感觉。
- 今日 Tab 内容较长，首屏需要连续滚动才能看到完整信息。
- 报告 Tab 三个大粉色指标卡高度较高，信息密度不够。
- Chart.js 默认网格线和横轴标签较重，图表不够轻量。
- 头部的大面积装饰形状容易抢占标题注意力。
- 底部三个操作按钮视觉权重接近，清空操作需要更明确的危险级别。

### 4.2 交互问题

- 当前四个 Tab 是固定信息架构，缺少自定义时间范围。
- 观看记录只能搜索和按完播状态筛选，不能按时长、进度、最近观看排序。
- 点击记录没有详情视图。
- 缺少“本周洞察”和与上周期的自然语言总结。
- 缺少用户目标，例如每周观看时长目标或完播目标。
- 深色模式尚未实现。

## 5. 后续设计方向

### 5.1 推荐方向：Bilibili Studio

视觉关键词：

- 白色和浅灰作为主要背景。
- B 站粉色只用于选中态、重点数字、主按钮和进度状态。
- 正文使用深灰，辅助信息使用中灰。
- 图表使用少量语义色：粉色代表主指标，绿色代表提升，橙色代表提醒。
- 降低圆角、阴影和装饰数量，让数据成为视觉焦点。

定位：像一个轻量个人观看数据工作台，而不是营销卡片页面。

### 5.2 建议设计令牌

使用 CSS 自定义属性集中管理颜色、间距、圆角和阴影。不要在组件内继续散落颜色值。

```css
:host {
  --bwp-bg: #f6f7f9;
  --bwp-surface: #ffffff;
  --bwp-surface-muted: #f1f3f5;
  --bwp-text: #18191c;
  --bwp-text-secondary: #61666d;
  --bwp-text-muted: #9499a0;
  --bwp-border: #e8eaed;
  --bwp-pink: #fb7299;
  --bwp-pink-soft: #fff0f5;
  --bwp-success: #2f9e70;
  --bwp-warning: #e89a3d;
  --bwp-danger: #d9485f;
  --bwp-radius-sm: 8px;
  --bwp-radius-md: 12px;
  --bwp-radius-lg: 16px;
  --bwp-space-1: 4px;
  --bwp-space-2: 8px;
  --bwp-space-3: 12px;
  --bwp-space-4: 16px;
  --bwp-space-5: 20px;
  --bwp-shadow-sm: 0 2px 8px rgba(24, 25, 28, .05);
  --bwp-shadow-md: 0 8px 24px rgba(24, 25, 28, .10);
}
```

这些变量属于[设计令牌（Design Token）](https://vibe-hub.org/design-token)，用于集中复用颜色、间距、字体和圆角值。

## 6. 推荐开发路线

### v0.5：视觉现代化

目标：不改变已有数据口径和四个 Tab 的主要功能，只优化表现层和信息层级。

任务：

1. 将面板背景改为浅灰，卡片改为白色。
2. 粉色只保留给激活态、重点指标、主操作和进度条。
3. 抽离 CSS 设计令牌，替换散落色值。
4. 今日 Tab 改成“概览 + 质量指标 + 趋势 + 记录”的层级。
5. 报告 Tab 改成一个主指标加两个紧凑指标，减少大面积粉色。
6. 图表隐藏多余边框和网格线，减少横轴标签倾斜。
7. 清空按钮改为低强调危险操作，增加 hover 和 focus 状态。
8. 保留 Shadow DOM、四个 Tab、导出和导入行为。

验收：

- 旧版记录仍能正常显示。
- 四个 Tab 名称不变。
- 质量指标数值不变。
- 面板在 1280px 桌面和 390px 移动宽度下不溢出。
- 图表关闭时全部销毁。
- `node --check` 通过。

### v0.6：数据洞察和时间范围

任务：

1. 新增时间范围：今日、本周、近 30 天、全部。
2. 新增“本周洞察”区块，全部由本地统计规则生成。
3. 增加与上周期的观看时长、视频数、完播率和平均进度对比。
4. 全部记录支持按最近观看、观看时长、进度排序。
5. 增加每周观看目标和完成进度。
6. 目标配置存入 `GM_getValue/GM_setValue`，不新增服务器或账号体系。

建议洞察文案：

```text
本周观看 12 个视频，比上周多 3 个。
平均进度 68%，完播率较上周提升 12%。
晚上 20:00 - 23:00 是你的主要观看时段。
重复观看最多的视频是《示例标题》。
```

文案必须根据真实数据生成；无数据时显示明确空状态，不伪造结论。

### v0.7：播放会话增强

任务：

1. 记录每次播放会话开始和结束时间。
2. 记录暂停次数、切后台次数和跳转次数。
3. 点击观看记录打开详情抽屉。
4. 详情展示：总观看时长、最高进度、完播状态、播放会话数、首次观看、最近观看。
5. 增加“中断率”和“平均单次会话时长”。

注意：这是数据模型升级，应先设计 schema v3 和迁移规则，再改采集逻辑。

状态：已完成。当前脚本为 v0.7.0，支持会话采集、会话统计、记录详情抽屉、v2 数据兼容和会话去重导入。

## 7. 不可破坏的技术约束

- 继续使用原生 JavaScript，不引入 React、Vue、Tailwind 或构建工具。
- 继续使用 Shadow DOM，避免污染 B 站页面。
- 继续使用 `GM_getValue/GM_setValue/GM_deleteValue` 做本地存储。
- 不新增服务器，不上传观看数据。
- 不为统计总时长增加批量接口请求。
- 不把 `watchedSeconds` 当成观看进度。
- 不用 `openCount` 冒充 `playCount`。
- 不根据旧记录的累计观看秒数伪造完播结果。
- 不改变现有四个 Tab 的名称和主要使用路径。
- 图表必须沿用 `makeChart()` 生命周期。
- 所有采集和渲染主流程都要有失败隔离。
- 维持本地时区和 `date + bvid` 的历史统计口径。
- 任何 schema 变化都必须兼容旧 JSON 备份。
- 优先修改同一个单文件，不拆分成多个运行文件。

## 8. 开发检查命令

在仓库根目录执行：

```powershell
node --check bilibili-watch-panel.user.js
git diff --check
git status --short
```

检查是否新增数据外发：

```powershell
rg -n "fetch\\(|XMLHttpRequest|sendBeacon" bilibili-watch-panel.user.js
```

预期：`fetch(` 只保留原有视频信息兜底请求；不应出现 `XMLHttpRequest` 或 `sendBeacon`。

浏览器验证重点：

- 首页、视频页都能打开浮动按钮。
- 视频播放时观看时长和最高位置正常变化。
- 暂停、切后台不累计。
- 播放会话和重复观看次数正确。
- 完播状态只从 `false` 变为 `true`。
- 四个 Tab 指标和图表正常。
- 图表关闭后销毁。
- 报告导出 PNG 不出现空白区块。
- 旧 JSON 导入后字段自动补齐。

## 11. 交接注意事项

- 当前截图里的数据是示例数据，不要把截图中的标题、UP 主和时长写死到代码中。
- 现有用户可能已经有 v1 或 v2 的本地数据，任何字段修改都必须通过 `sanitizeRecord()` 或迁移入口处理。
- 真实浏览器验证需要安装 Tampermonkey 并注入用户脚本；普通 Playwright 访问 B 站不会自动加载本地用户脚本。
- 如果网络不可用，不能把 CDN 图表库失败误判为统计逻辑失败。
- 如果修改 UI，优先保留现有 DOM 行为和事件绑定，再调整结构和样式。
- 不要为了“现代化”加入渐变背景、装饰性光斑、无意义的卡片或虚构洞察。
