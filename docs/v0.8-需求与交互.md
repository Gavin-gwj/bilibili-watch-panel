# v0.8 需求与交互规格

> 状态：已实现并按用户确认先行发布，真实页面验收待完成 · 2026-10-03
> 基线：`v0.7.1`；v0.8 已于 2026-10-03 按用户确认先行发布；开发验证与未覆盖项见 [测试结果](./v0.8-测试结果.md)。
> 配套文档：[技术实现](./v0.8-技术实现.md) · [测试与验收](./v0.8-测试与验收.md)

## 1. 版本目标

把“能看统计”提升为“能稳定、舒适、可控地长期使用”。v0.8 专注**设置与体验**，不新增观看数据的统计口径、不扩展采集范围、不引入云端服务。

| 优先级 | 目标 | 用户可观察结果 |
| --- | --- | --- |
| P0 | 找回悬浮按钮 | 在设置里重置按钮位置，不清除观看记录；浏览器缩放后仍在可视区域 |
| P0 | 显示个性化 | 可设置面板宽度、按钮尺寸；刷新和切页后保留 |
| P0 | 主题 | 浅色、深色、跟随系统；面板、弹窗及图表文字可读 |
| P1 | 提醒与键盘 | 可关每周提醒，可选快捷键打开面板；Esc 能按层级关闭 |
| P1 | 数据健康 | 只读检测记录异常与重复，清楚告诉用户何处可能存在问题 |

### 不在 v0.8 中做

自定义日期区间、UP 主分析页、播放会话时间线、标签/分区分析、自动修复数据、云同步、隐藏悬浮按钮、自定义快捷键、更多主题色。保留现有「今日 / 本周 / 全部 / 报告」四个 Tab；**设置不是第五个统计 Tab**。

## 2. 用户路径与界面

```text
悬浮按钮 → 面板（今日 / 本周 / 全部 / 报告）
                    │
                    └─ 顶部「设置」图标 → 设置视图
                                          ├─ 外观
                                          ├─ 操作与提醒
                                          └─ 数据健康检查
```

- 头部在关闭按钮旁新增带可见焦点态和 `aria-label="打开设置"` 的设置按钮；保留原有四个 Tab、底部 JSON 操作栏和已打开 Tab 的状态。
- 设置视图沿用同一抽屉，不叠加第二个大面板；返回时回到进入设置前的 Tab，原有数据不重置。
- 外观项实时预览；改变主题或宽度时不丢失滚动以外的用户状态（搜索词、当前 Tab、面板开关）。若渲染重建不可避免，至少保持当前 Tab 和输入值。
- 小视口下设置页可纵向滚动，底部导入/导出/清空操作不可与设置控件重叠。危险操作仍需现有双重确认。

### 2.1 外观设置

| 设置项 | 取值及默认值 | 交互及约束 |
| --- | --- | --- |
| 主题 | `system`（默认）、`light`、`dark` | 选择后立即生效；跟随系统时响应系统外观变化；不改变 B 站原页面 |
| 面板宽度 | 320–520 CSS px、步长 20、默认 380 | 数值标签同步更新；最终宽度不得超过可视区域；窄屏优先铺满可视区域 |
| 悬浮按钮尺寸 | 40 / 48 / 56 CSS px，默认 48 | 图标与按钮一起缩放；可继续拖动，拖后仍贴边且不越界 |
| 重置按钮位置 | 不存布尔状态 | 一次点击清除已存拖拽坐标，并把按钮放回当前视口右上方、安全边距内；不清除其他设置 |
| 恢复默认外观 | 不存状态 | 仅恢复主题、宽度、按钮尺寸、按钮位置；不改变提醒、快捷键、观看记录和周目标；需在按钮文案中写明范围 |

**不提供“隐藏悬浮按钮”开关**：此版本尚无可靠的跨页面恢复入口，避免用户把插件隐藏后无法进入设置。

### 2.2 操作与提醒

| 设置项 | 默认 | 交互 |
| --- | --- | --- |
| 每周报告提醒 | 开 | 关闭后，周日打开 B 站不弹提醒；已经展示的提示立即移除；重新开启不会在同一周重复提醒 |
| 面板快捷键 | 关 | 开启后 `Alt+Shift+W` 切换面板开关；若浏览器/系统占用此组合，以浏览器行为为准，仍可点击悬浮按钮 |

- 快捷键仅在当前 B 站页生效；不处理按键连发，不在输入框、文本域、下拉控件、`contenteditable` 内触发；不要求网页以外的全局热键能力。
- `Esc`：若打开记录详情，先返回详情；若在设置视图，先返回原 Tab；否则关闭面板。不会清除设置。
- 周日提醒关闭时不写入“已提醒周”标记；重新开启时是否显示以该周此前是否提醒过为准。

### 2.3 数据健康检查

在设置页提供“开始检查”。检查针对当前本地存储**只读**执行，显示扫描时间、主记录数、归档记录数及问题数量；无问题显示“未发现已定义的异常”，不承诺数据绝对正确。

| 问题类别 | 检测规则（以原始数据为准） | 反馈 |
| --- | --- | --- |
| 存储格式错误 | 主/归档 key 非数组，或读取抛错 | 显示存储项及错误类别；无法读取时结果为“检查未完成”而非“健康” |
| 无效记录 | 不满足现有 `isValidRecord` 最低合法性要求 | 按主记录 / 归档分别计数，不直接显示用户视频标题 |
| 重复记录 | 同一集合内部或跨主/归档出现相同 `date + bvid` | 列出重复组数和涉及条数，不自动合并 |
| 非法数值 | 时长为负/非有限、已知视频总长为负、最高播放位置为负/非有限 | 指明类别和数量；不把高倍速观看或重看时长大于视频总长误判为错误 |
| 会话异常 | `sessions` 非数组，或单个会话不满足现有 `sanitizeSession` 的起止时间等条件 | 计数；旧记录缺少 `sessions` 时视为兼容旧数据，不报错 |
| 数据容量提示 | 达到现有归档裁剪提示 `archiveNotice` | 标注“部分最旧记录曾被裁剪”，提醒备份，不伪称可恢复 |

- 点击再次检查后重读原始存储；不在每个页面心跳执行，不把检查结果写入存储。
- **不提供“自动修复”**。对于异常数据，说明当前导出 JSON 使用已清洗的有效记录，可能不包含损坏条目；不能把“导出成功”写成“完整无损备份”。
- 若健康检查遇到读取错误，其他面板功能沿用既有容错策略，不能因检查崩溃。

## 3. 验收边界

| 场景 | 必须达到 |
| --- | --- |
| 老用户升级 | 原有记录、归档、周目标、按钮位置和已提醒周不变；缺少设置值时使用默认值 |
| 不同缩放 | 80%、90%、100%、125% 下按钮可见、可点击；重置位置后仍可拖动 |
| 深色模式 | 面板各 Tab、设置视图、详情抽屉、提示条、图表坐标轴均可读，至少不出现白底白字/黑底黑字 |
| 报告导出 | 不受当前主题影响；保持既有白底 PNG 样式与内容完整 |
| 移动/窄视口 | 面板不横向溢出，设置可滚动，按钮可回到视口内 |
| 数据完整性 | 单纯改设置/检查健康度不写入或删除观看记录；清空数据仍按原有双重确认执行 |
